# Fenina API — Backend for the admin dashboard

Django REST API powering the Fenina auto-parts admin dashboard. Handles staff
authentication, clients, stock, invoices, payments, payment reminders, and a
daily revenue snapshot.

The same API also serves the customer storefront later — it's the shared
backend both frontends talk to.

---

## What's inside

| App | Responsibility |
|-----|----------------|
| `accounts` | Staff users + JWT login (roles: owner / manager / employee) |
| `catalog`  | Clients (garages & individuals) and stock parts |
| `billing`  | Invoices, line items, payments, reminders, dashboard metrics |

Money is stored with **3 decimal places** (Tunisian Dinar convention).
Invoice status (`paid` / `partial` / `unpaid`) is **computed from payments**,
never set by hand — so it can't drift out of sync.

## 1. Setup (local dev, SQLite — fastest start)

You need **Python 3.11+**.

```bash
cd fenina-api

# create a virtual environment
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# install dependencies
pip install -r requirements.txt

# create your env file
cp .env.example .env             # Windows: copy .env.example .env

# create the database tables
python manage.py migrate

# (optional) load sample data + a test login
python seed.py

# run the server
python manage.py runserver
```

API is now at **http://localhost:8000/**.

## 2. Switching to PostgreSQL

SQLite is fine for development. For the real deployment, use PostgreSQL.

1. Install PostgreSQL and create a database + user:

   ```sql
   CREATE DATABASE fenina_db;
   CREATE USER fenina_user WITH PASSWORD 'yourpassword';
   GRANT ALL PRIVILEGES ON DATABASE fenina_db TO fenina_user;
   ```

2. In your `.env`, set:

   ```
   DATABASE_URL=postgres://fenina_user:yourpassword@localhost:5432/fenina_db
   ```

3. Re-run migrations against Postgres:

   ```bash
   python manage.py migrate
   python seed.py        # optional sample data
   ```

The app auto-detects `DATABASE_URL`: if it's set, it uses Postgres; if empty,
it falls back to SQLite. No code changes needed.

## 3. Create a real admin user

For production, don't use the seed login. Create your own:

```bash
python manage.py createsuperuser
```

You can also manage everything through Django's built-in admin at
**http://localhost:8000/django-admin/**.

## 4. The daily reminder job

Overdue-payment reminders are generated by a management command:

```bash
python manage.py run_reminders
```

It scans every unpaid/partial invoice and creates a reminder when an invoice
crosses an overdue milestone (1, 7, 14, 30 days). It's **idempotent** — safe to
run repeatedly; it won't create duplicates.

Schedule it to run once a day:

**Linux / macOS (cron):** run `crontab -e` and add (runs every day at 08:00):

```
0 8 * * * cd /full/path/to/fenina-api && /full/path/to/.venv/bin/python manage.py run_reminders
```

**Windows (Task Scheduler):** create a Basic Task → Daily → Action "Start a
program":
- Program: `C:\full\path\to\fenina-api\.venv\Scripts\python.exe`
- Arguments: `manage.py run_reminders`
- Start in: `C:\full\path\to\fenina-api`

## 5. API reference

All endpoints are under `/api/`. Except for login, every request needs an
`Authorization: Bearer <access_token>` header.

### Auth
| Method | Path | Purpose |
|--------|------|---------|
| POST | `/api/auth/login/` | Log in with `email` + `password`; returns `access`, `refresh`, and `user` |
| POST | `/api/auth/refresh/` | Exchange a refresh token for a new access token |
| GET  | `/api/auth/me/` | Current staff profile |

### Invoices
| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/invoices/` | List (supports `?search=`, `?status=unpaid`, `?overdue=true`) |
| POST | `/api/invoices/` | Create (nested `lines`) |
| GET | `/api/invoices/{id}/` | Retrieve one (with lines, payments, totals) |
| PATCH/PUT | `/api/invoices/{id}/` | Update (replacing `lines` replaces all of them) |
| DELETE | `/api/invoices/{id}/` | Delete |
| POST | `/api/invoices/{id}/add_payment/` | Record a payment: `{ "amount": "100", "method": "cash" }` |

### Clients & Parts
| Method | Path |
|--------|------|
| CRUD | `/api/clients/` (search by name/phone/email) |
| CRUD | `/api/parts/` (search by name/sku/brand; `?low_stock=true`) |

### Reminders
| Method | Path | Purpose |
|--------|------|---------|
| GET | `/api/reminders/` | List generated reminders |
| POST | `/api/reminders/refresh/` | Regenerate now (same logic as the daily job) |
| POST | `/api/reminders/{id}/mark_sent/` | Mark a reminder as sent |

### Dashboard
| Method | Path | Returns |
|--------|------|---------|
| GET | `/api/dashboard/` | `revenue_today`, `invoiced_today`, `outstanding`, `overdue_count`, `overdue_total`, and a 7-day `revenue_trend` |

## 6. Example: login then create an invoice

```bash
# login
curl -X POST http://localhost:8000/api/auth/login/ \
  -H "Content-Type: application/json" \
  -d '{"email":"amir@fenina.tn","password":"fenina2026"}'

# create an invoice (use the access token from the response above)
curl -X POST http://localhost:8000/api/invoices/ \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
        "client": 1,
        "due_date": "2026-06-30",
        "lines": [
          {"description": "Plaquettes Bosch", "quantity": "4", "unit_price": "95"}
        ]
      }'
```

## 7. Connecting the React admin dashboard

The dashboard (`admin/` folder, `FeninaAdmin.jsx`) currently uses in-memory
sample data. To connect it to this API:

1. Store the JWT `access` token after login (e.g. in React state / context).
2. Replace the `seedInvoices` array and CRUD handlers with `fetch` calls to the
   endpoints above, sending the `Authorization: Bearer` header.
3. The dashboard's revenue card maps directly onto `GET /api/dashboard/`, and
   the reminders page onto `GET /api/reminders/`.

The CORS settings already allow `http://localhost:5173` (Vite's default), so the
admin can call the API during development without extra configuration.
